KrakenLink bench demo (no hardware needed)
==========================================
Run each step in its OWN terminal, in this order, starting from:
    cd ~/Storage/Kraken_KD_ws/krakenlink

1) Terminal 1: fake Kraken (simulator)
    python -m krakenlink.sim --directory bench/share --port 18081 --calibration-gap 3

2) Terminal 2: bridge daemon (the part that runs on the Pi)
    python -m krakenlink.bridge --config bridge.bench.toml

3) Terminal 3: ground station app
    python -m krakenlink.ground --config ground.example.toml

4) Open in a browser:
    http://127.0.0.1:8050

Things to try
-------------
- Settings panel: set the center frequency to 433500000 Hz.
  The command shows accepted, then done after about 4 s (simulated calibration).
- Link loss: press Ctrl+C in terminal 2. The link panel goes DEGRADED, then LOST.
  Rerun step 2 and it comes back UP.
- Kraken down: press Ctrl+C in terminal 1. The Kraken state goes STALE, then DOWN.
  Rerun step 1 and data resumes.

Stop everything: press Ctrl+C in each terminal (3, then 2, then 1).

Optional: run the tests
    PYTEST_DISABLE_PLUGIN_AUTOLOAD=1 python -m pytest -q tests


REAL system: Pi 5 (official KrakenSDR image) -> ESP-NOW -> laptop ground app
==============================================================================
Pi is 192.168.50.5 (user krakenrf). Kraken runs from the image's own service.
Our bridge lives only in ~/krakenlink on the Pi and starts on boot
(systemd unit krakenlink-bridge.service). Details: deploy/krakenimage/README.md

Both ESP32-S3 boards must be plugged into their "COM" USB port (not "USB"):
  AIR    -> Pi       (firmware: pio run -d firmware/esp32_link -e air_s3 -t upload)
  GROUND -> laptop   (firmware: pio run -d firmware/esp32_link -e ground_s3 -t upload)

1) Power the Pi + KrakenSDR. Nothing to type: Kraken and the bridge start on boot.

2) On the laptop:
    cd ~/Storage/Kraken_KD_ws/krakenlink
    python3 -m krakenlink.ground --config ground.espnow.toml

3) Open http://127.0.0.1:8050
   DOA/compass only move when a signal opens the VFO squelch in Kraken
   (Kraken UI: http://192.168.50.5:8080).

Bridge on the Pi (ssh krakenrf@192.168.50.5, then cd ~/krakenlink):
    ./run_bridge.sh status                      is it running, which ESP port
    ./run_bridge.sh log                         last 40 log lines
    sudo systemctl restart krakenlink-bridge    restart (e.g. after replugging the ESP32)
    sudo systemctl stop krakenlink-bridge       stop until next boot
    ./run_bridge.sh remove-service              stop starting on boot

After changing code on the laptop, copy it to the Pi and restart the bridge:
    deploy/krakenimage/push.sh

Note: ground -> Pi commands (retune etc.) are refused for now: the bridge runs as
krakenrf and Kraken's settings.json is root-owned.
